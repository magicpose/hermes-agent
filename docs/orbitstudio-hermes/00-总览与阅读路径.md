# 00-总览与阅读路径

## 1. 文档定位
本套文档是 Hermes fork 的实施蓝图，服务对象是：
- 需要在 OrbitStudio 内嵌 Hermes 的研发团队。
- 需要保证多助理并发隔离的后端开发者。
- 需要编写测试与验收用例的 QA 与联调同学。

本套文档解决的核心问题：
- 如何在单进程中让多个 AIAgent 使用不同数据目录。
- 如何保证 MEMORY、skills、配置、会话日志不串写。
- 如何让协作组在保留成员独立记忆的前提下支持多策略编排。

## 2. 设计目标一句话
将 Hermes 从“进程级 HERMES_HOME 隔离”扩展为“实例级 `hermes_home` 隔离”，并在 CollabGroup 中采用“模型 B 主线 + 协调器可选”。

## 3. 阅读路径（0→N）
1. `01-目标与非目标.md`
- 确认本次改造要解决什么，不解决什么。

2. `02-现状盘点与问题清单.md`
- 确认当前实现的真实风险点，避免“感觉式重构”。

3. `03-实例级HermesHome模型设计.md`
- 锁定核心契约：身份、目录、实例变量、默认回退。

4. `04-运行时透传链路设计.md`
- 锁定参数如何从 Orbit 传到工具层，避免半程丢参。

5. `05-Memory与Skills隔离设计.md`
- 锁定最容易串写的数据面：memory 与 skills。

6. `06-缓存与快照隔离设计.md`
- 锁定缓存污染问题，防止“看起来隔离、实际共享”。

7. `07-委派与后台评审一致性设计.md`
- 锁定子代理、自进化链路的同目录一致性。

8. `08-OrbitStudio接入规范.md`
- 锁定运行接入方式与组运行接口。

9. `12-协作组编排与协调器策略设计.md`
- 锁定 CollabGroup 策略枚举、降级规则与观测指标。

10. `10-11`
- 测试验收与实施排期。

## 4. 实施原则
- 兼容优先：新增参数必须可选，旧调用不改也可运行。
- 单一事实源：每个 AIAgent 实例只认 `self._hermes_home`。
- 透传到底：运行时上下文不得在工具层回退到进程级全局路径。
- 协作组主线明确：持久组只走模型 B，模型 A 不进入持久协议。
- 文档先行：编码前先冻结接口与目录契约。
