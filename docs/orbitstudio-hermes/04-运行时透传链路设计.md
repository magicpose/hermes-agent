# 04-运行时透传链路设计

## 1. 目标
把 `hermes_home` 从 Orbit 入口稳定传到 Hermes 工具执行层，避免中途丢失。

## 2. 单助理端到端链路

Orbit Client：
1. 根据 `tenant_id/studio_id/assistant_id` 计算实例目录。
2. 创建 `AIAgent(hermes_home=...)`。

Hermes Runtime：
3. `AIAgent.__init__` 保存 `self._hermes_home`。
4. `run_conversation`、`_invoke_tool` 在调用工具时附带 `hermes_home`。
5. `model_tools.handle_function_call` 增加可选参数并向 `registry.dispatch` 透传。
6. tools handler 从 `kw` 获取 `hermes_home`，作为路径解析依据。

## 3. Group Run 链路（冻结）

### 3.1 `sequential`
- Orbit 按成员顺序逐个调用成员 AIAgent。
- 每个成员使用自己目录。
- 上一成员输出作为下一成员输入上下文。

### 3.2 `parallel`
- Orbit 并发调用多个成员 AIAgent。
- 每个成员仍使用自己目录。
- Orbit 负责聚合输出与冲突合并。

### 3.3 `coordinator`
- Orbit 先调用组协调器 AIAgent。
- 协调器返回执行计划：调用顺序、上下文裁剪、成员路由。
- Orbit 按计划调用成员 AIAgent 执行。
- 协调器失败或超时自动回退 `sequential`。

## 4. 函数签名变更点（冻结）

### 4.1 run_agent 层
- `_invoke_tool(...)` 内调用 `handle_function_call(..., hermes_home=...)`。
- 并发工具调用分支同样透传。

### 4.2 model_tools 层
```python
def handle_function_call(
    function_name: str,
    function_args: Dict[str, Any],
    task_id: Optional[str] = None,
    ...,
    hermes_home: Optional[str] = None,
) -> str:
    ...
```

### 4.3 registry 层
- `registry.dispatch(name, args, **kwargs)` 无需改签名，但必须透传 `hermes_home` 到 handler。

## 5. handler 接口约定
skills/memory 相关 handler 统一约定：
- 可从 `kw.get("hermes_home")` 读取实例目录。
- 不存在时回退原有默认行为。

## 6. 语义边界
- `delegate_task` 是单成员 Agent 内部分解能力。
- CollabGroup 跨成员编排由 Orbit 执行，不用 `delegate_task` 替代。

## 7. 非本期范围
- API Server `/v1/runs` 协议新增字段及多实例调度，不在本期落地。
- Gateway 多平台 session 路由体系不在本期重构。

## 8. 容错与日志
- 透传参数为空时不报错，走默认路径。
- 透传参数非法（非路径字符串）时记录 warning 并抛出参数错误。
- Group Run 需记录策略、成员顺序、降级事件，便于审计与排障。
