# 06-缓存与快照隔离设计

## 1. 目标
防止不同助理实例在 skills prompt 生成阶段发生缓存串用和快照串读。

## 2. 现有机制
`build_skills_system_prompt` 目前存在两层优化：
1. 进程内 LRU cache
2. 磁盘 snapshot（`.skills_prompt_snapshot.json`）

这两层机制若不纳入 `hermes_home` 维度，会在单进程多实例下造成污染。

## 3. 设计原则
1. 缓存 key 必须包含 `hermes_home`。
2. snapshot 路径必须位于实例目录下。
3. 缓存失效逻辑必须基于“该实例目录”的技能文件 manifest。

## 4. 契约冻结

### 4.1 snapshot path
```python
_skills_prompt_snapshot_path(hermes_home: Path | None = None) -> Path
```

行为：
- `hermes_home` 不为空：`Path(hermes_home) / ".skills_prompt_snapshot.json"`
- 否则：沿用 `get_hermes_home()`

### 4.2 cache key
`build_skills_system_prompt` 的 cache key 必须至少包含：
- `resolved_hermes_home`
- `skills_dir`
- `external_dirs`
- `available_tools`
- `available_toolsets`
- `platform_hint`

说明：
- 若未包含 `resolved_hermes_home`，不同实例会错误共用缓存。

## 5. 并发策略
- 沿用现有 `_SKILLS_PROMPT_CACHE_LOCK`。
- 锁粒度不扩大，不引入全局大锁。
- 允许不同实例在同进程并发读写各自 snapshot 文件（路径不同）。

## 6. 错误处理
- snapshot 解析失败：仅跳过 snapshot，回退文件扫描，不影响主流程。
- snapshot 写入失败：记录 debug/warning，不阻塞对话。

## 7. 验收点
1. 不同 `hermes_home` 的两个实例，同步触发 skills prompt 构建时，cache 命中互不影响。
2. 删除实例 A snapshot 文件，不影响实例 B。
