# 02-现状盘点与问题清单

## 1. 现状结论
Hermes 中大量路径解析已采用 `get_hermes_home()` 动态调用，这是本次改造可行性的基础。

但仍存在关键全局化路径与静态常量，导致“单进程多助理”场景会串写。

## 2. 关键问题清单

### P0-1：Skills 路径存在模块级静态目录
- `tools/skills_tool.py` 与 `tools/skill_manager_tool.py` 在模块加载时构造 `SKILLS_DIR`。
- 风险：同进程多个 AIAgent 使用同一个 skills 根目录。

### P0-2：AIAgent 内部仍有进程级 home 读写点
- 日志目录、memory provider 初始化、context engine session start 等位置直接调用全局 `get_hermes_home()`。
- 风险：实例参数存在但未完全生效，形成“伪隔离”。

### P0-3：Tool 调度链无 `hermes_home` 上下文
- `run_agent -> model_tools -> registry -> tool handler` 缺少实例目录透传字段。
- 风险：工具函数回退到默认路径，导致跨助理污染。

### P1-1：skills prompt 缓存未纳入 home 维度
- `build_skills_system_prompt` 存在进程内 cache 与 snapshot。
- 风险：不同助理可能命中同一缓存结果。

### P1-2：skill config 读取链路未全量支持 home 透传
- `skill_utils` 部分函数读取 `config.yaml` 仍走默认路径。
- 风险：助理 A 的技能配置影响助理 B。

### P1-3：后台评审/委派未显式绑定实例 home
- `_spawn_background_review` 与 `delegate_tool` 默认未绑定实例 home。
- 风险：主代理隔离了，子代理仍写全局。

## 3. 可行性结论
本次改造可以通过“参数透传 + 局部去静态化”完成，不需要推翻 Hermes 架构。

本质是：
- 把“路径来源”从进程全局改为实例优先。
- 把“链路上下文”从隐式环境改为显式参数。

## 4. 风险排序
1. 先清 P0（不清会直接串写）。
2. 再清 P1（不清会产生隐性污染与难定位问题）。
