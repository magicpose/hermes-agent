# 12-协作组编排与协调器策略设计

## 1. 背景
协作组的关键问题是：组成员是否需要各自持久记忆。

如果组成员是“有专长的持久助理”，必须保证成员记忆与技能隔离。

## 2. 模型对比结论（冻结）

### 2.1 模型 A：组 = 单个 Agent 角色扮演
- 形式：一个 AIAgent，在 prompt 中描述多角色。
- 优点：调用简单，一次执行。
- 缺点：成员记忆混在同一 MEMORY/skills，无法持久隔离。

### 2.2 模型 B：组 = Orbit 编排多个独立 AIAgent
- 形式：每个成员独立 `hermes_home`，由 Orbit 编排执行。
- 优点：成员记忆与技能可持续进化且互不污染。
- 缺点：多次调用，编排复杂度更高。

### 2.3 持久协作组主协议
- 持久 CollabGroup 固定采用模型 B。
- 模型 A 仅作为一次性临时协作概念，不进入持久协议。

## 3. 策略矩阵

| 策略 | 触发场景 | 执行方式 | 记忆归属 | 失败处理 |
|---|---|---|---|---|
| sequential | 默认/稳定流程 | 成员按顺序执行 | 成员各自目录 | 失败即中止或按上层重试策略 |
| parallel | 可并发子任务 | 成员并发执行后聚合 | 成员各自目录 | 子任务失败按聚合策略回退 |
| coordinator | 复杂动态协作 | 先由协调器决策再调成员 | 协调器与成员各自目录 | 协调器失败自动降级 sequential |

冻结契约：
- `CollabGroup.strategy` 枚举：`sequential | parallel | coordinator`
- 默认值：`sequential`

## 4. 关键责任边界
1. Orbit 编排层负责跨成员执行顺序与上下文路由。
2. Hermes 成员 Agent 负责各自执行与各自进化。
3. 协调器 Agent 只负责步骤决策与上下文裁剪，不替代成员执行。
4. `delegate_task` 仅用于单成员 Agent 内部分解，不用于跨成员编排。

## 5. 时序流程

### 5.1 sequential
1. Orbit 读取组成员顺序。
2. 调成员 A，获得输出 A。
3. 将输出 A 作为上下文传给成员 B。
4. 持续到最后成员并返回组输出。

### 5.2 parallel
1. Orbit 拆分任务为并发子任务。
2. 并发调用多个成员。
3. 聚合结果并生成组输出。

### 5.3 coordinator
1. Orbit 调用协调器 Agent。
2. 协调器输出执行计划（顺序、路由、上下文裁剪）。
3. Orbit 按计划调成员执行。
4. 若协调器失败或超时，自动切换 sequential。

## 6. 失败降级契约（冻结）

### 6.1 降级触发条件
- 协调器调用超时
- 协调器返回不可解析计划
- 协调器执行异常

### 6.2 降级行为
- 当前 group run 直接回退 `sequential`。
- 记录降级事件：`group_id`, `run_id`, `reason`, `fallback_strategy`。
- 不改变组的持久配置，仅影响当前运行。

## 7. 观测指标
1. `group_run.total`
2. `group_run.by_strategy`
3. `group_run.coordinator.fallback_total`
4. `group_run.member.latency_ms`
5. `group_run.member.error_rate`
6. `group_run.output.merge_conflict_total`

## 8. 验收口径
1. 同组成员多轮运行后，记忆与技能不互相污染。
2. 三策略运行轨迹可区分，可复现。
3. 协调器故障时，顺利降级并完成闭环。
4. 文档与实现中策略枚举、默认值、降级规则保持一致。
