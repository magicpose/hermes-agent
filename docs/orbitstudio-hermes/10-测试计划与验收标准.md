# 10-测试计划与验收标准

## 1. 测试目标
验证 `per-instance hermes_home` 改造在功能正确性、隔离性、兼容性上的完整闭环，并覆盖协作组策略行为。

## 2. 测试分层

### 2.1 单元测试（函数/模块级）
1. `MemoryStore`：
- 传 `hermes_home` 时读写实例目录。
- 不传时保持默认目录。

2. `skill_utils`：
- disabled/external/all/config 解析函数在传入 home 时读取对应 config。

3. `build_skills_system_prompt`：
- cache key 包含 home。
- snapshot 路径跟随 home。

4. 协作组策略解析：
- `strategy` 只接受 `sequential|parallel|coordinator`。
- 默认值为 `sequential`。

### 2.2 集成测试（AIAgent 级）
1. 双实例隔离：
- 同进程创建 agent A/B，分别写 memory 和 skill，互不污染。

2. 背景评审一致性：
- 触发 review 后写入路径与主代理一致。

3. 委派一致性：
- delegate 子代理执行后，路径归属与父代理一致。

### 2.3 协作组专项测试
1. 成员隔离：
- 同组成员多轮运行后，`MEMORY.md` 与 `skills/` 不互相污染。

2. 策略一致性：
- `sequential`、`parallel`、`coordinator` 输出与审计轨迹可区分且可复现。

3. 协调器持久性：
- 协调器可跨运行保留协作偏好，不影响成员记忆隔离。

4. 降级可用性：
- 人为注入协调器失败后，自动降级 `sequential` 并完成任务闭环。

5. 边界正确性：
- `delegate_task` 调用不跨成员写入。
- CollabGroup 编排不依赖单 Agent 角色扮演模型。

### 2.4 回归测试（兼容）
1. 不传 `hermes_home`：
- 关键路径行为与基线版本一致。

2. 现有工具功能：
- `skills_list/skill_view/skill_manage/memory` 旧调用方式不报错。

## 3. 场景验收（冻结）
必须覆盖以下六类场景：
1. 单机双助理并发
2. 后台评审写入
3. 委派子代理协作
4. 默认兼容（不传参数）
5. 协作组三策略一致性
6. 协调器失败降级

## 4. 验收标准
1. 路径正确性：所有持久化文件写入到预期实例目录。
2. 互斥性：助理 A 的 memory/skills 不出现在助理 B 目录。
3. 兼容性：历史调用方无需改动即可运行。
4. 可追踪性：日志可定位每次运行使用的实例目录、组策略和降级事件。
5. 文档一致性：`strategy` 枚举、默认值、降级规则在全部文档保持一致。

## 5. 建议输出物
- 测试报告（按六类场景分节）
- 关键目录快照（tree + 文件摘要）
- 策略运行轨迹与降级事件样本
- 问题清单与修复闭环记录
