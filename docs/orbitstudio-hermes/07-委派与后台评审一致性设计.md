# 07-委派与后台评审一致性设计

## 1. 目标
确保主代理、委派子代理、后台评审代理在目录归属上保持一致，避免“主隔离、子串写”。

## 2. 背景
Hermes 中存在两类隐式派生代理：
1. `delegate_task` 子代理（`tools/delegate_tool.py`）
2. `_spawn_background_review` 评审代理（`run_agent.py`）

若不透传 `hermes_home`，这两类代理会回落进程级路径。

## 3. 设计要求

### 3.1 背景评审代理
在 `_spawn_background_review` 创建评审 AIAgent 时：
- 必须透传 `hermes_home=self._hermes_home`
- 保持与主代理相同模型与关键上下文
- memory/skills 写入应落同一实例目录

### 3.2 委派子代理
在 `delegate_tool._build_child_agent` 创建 child 时：
- 必须透传 parent 的 `hermes_home`
- 保持 `skip_memory=True` 的既有策略（如当前策略要求）
- 即便 skip memory，skills 与其他路径解析仍需使用同实例目录

### 3.3 Session 关联
- 子代理可继续复用 `session_db` 与 parent_session_id 语义
- 但任何文件路径仍以 child 的 `hermes_home` 解析

## 4. 语义边界（冻结）
1. `delegate_task` 仅用于单成员 Agent 内任务分解。
2. `delegate_task` 不等于 CollabGroup 多助理协作。
3. CollabGroup 跨成员协作由 Orbit 编排层负责。

## 5. 一致性规则（冻结）
1. 同一主会话衍生出的所有内部代理共享同一 `hermes_home`。
2. 不允许内部代理因默认参数回退到全局 home。
3. 不通过全局环境变量在运行中切换 home。

## 6. 验收点
1. 触发 background review 后，skills 更新落在当前 assistant 的 `skills/`。
2. 触发 delegate_task 后，子代理产生的相关持久数据不越界到其他 assistant 目录。
3. CollabGroup 运行时不依赖 `delegate_task` 替代跨成员编排。
