# 09-迁移兼容与回滚策略

## 1. 目标
在不影响现有 Hermes 使用者的前提下引入实例级目录能力，并支持快速回滚。

## 2. 兼容策略

### 2.1 默认兼容
- 所有新增参数均为可选。
- 不传 `hermes_home` 时，行为与现有版本一致。

### 2.2 渐进启用
- Orbit 侧按 assistant 逐步启用 `hermes_home`。
- 可先在灰度 studio 启用，验证稳定后全量。

## 3. 迁移策略
本轮不做自动迁移脚本，采用“新实例新目录”策略：
1. 新建 assistant 时直接使用新目录。
2. 旧全局数据保留只读可查（如需人工迁移可后续补工具）。

## 4. 回滚策略
如出现不可接受问题：
1. Orbit 停止传 `hermes_home` 参数。
2. Hermes 回退到全局 `get_hermes_home()` 模式。
3. 已生成的实例目录不删除，作为排障证据与后续恢复输入。

## 5. 风险与应对

### 风险 1：半链路透传导致伪隔离
- 应对：以“工具层最终路径”作为验收口径，而不是看入口参数。

### 风险 2：缓存污染
- 应对：在测试中加入不同 home 的缓存互斥用例。

### 风险 3：调用方漏传
- 应对：Orbit 封装统一工厂创建 AIAgent，禁止业务代码直连构造。

## 6. 发布建议
1. 先发文档与测试。
2. 再发代码改造。
3. 最后发布 Orbit 接入开关。
