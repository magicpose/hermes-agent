# 01-目标与非目标

## 1. 背景
OrbitStudio 需要让多个助理（AssistantRef）在同一 Client 内并发运行，并保留各自进化能力（memory 与 skills）。

Hermes 当前主能力是“基于 `HERMES_HOME` 的 profile 级隔离”，这在 CLI 或多进程部署中有效，但不足以覆盖 Orbit 需要的“单进程多实例隔离”。

## 2. 目标（Goals）
1. 支持 AIAgent 实例级 `hermes_home`
- 新增 `AIAgent.__init__(..., hermes_home: str | Path | None = None)`。
- 允许同进程内多个 AIAgent 指向不同目录运行。

2. 保证核心数据面隔离
- `memories/MEMORY.md`、`memories/USER.md`。
- `skills/`（含 SKILL.md 与 supporting files）。
- `config.yaml`、`.env`、`sessions/` 相关读取。

3. 保证链路闭环
- Orbit 传入的实例目录必须经运行时链路透传到工具层。
- 委派子代理与后台评审代理与主代理使用同一实例目录。

4. 保持默认兼容
- 不传 `hermes_home` 时，行为与当前版本一致（继续使用 `get_hermes_home()`）。

## 3. 非目标（Non-Goals）
1. 不在本轮实现 Hermes API Server 全面多租户化。
2. 不在本轮重构 CLI profile 命令体系。
3. 不引入 Openclaw 兼容层。
4. 不做旧数据自动迁移工具（仅保证新路径可用）。

## 4. 约束
1. 不破坏现有工具注册机制与调用方式。
2. 不引入必须修改大量现有调用方的位置参数变更。
3. 不以环境变量切换替代实例参数透传。

## 5. 成功标准
1. 单进程内 2 个 AIAgent 写入不同 `hermes_home`，数据互不污染。
2. 背景评审与 delegate 子代理写入与主代理一致。
3. 不传 `hermes_home` 的测试与原有行为保持一致。
4. 文档可直接指导研发实现与验收，无额外口头补充。
